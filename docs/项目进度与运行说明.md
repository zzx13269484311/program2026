## 5. 运行项目的完整步骤

### 5.1 打开 PowerShell

### 5.2 进入项目目录

```powershell
Set-Location "D:\program\weizhixianjue"
```

### 5.3 临时放行并激活 Python 虚拟环境

Windows 默认执行策略为 `Restricted`，因此直接运行 `Activate.ps1` 可能提示“禁止运行脚本”。

本项目统一使用**当前 PowerShell 窗口临时放行**的方式：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\.venv\Scripts\Activate.ps1
```

激活成功后，命令行前面通常会显示 `(.venv)`。

说明：

- `-Scope Process` 只影响当前 PowerShell 窗口。
- 关闭当前窗口后，执行策略自动恢复。
- 不会修改 `CurrentUser` 或 `LocalMachine` 的永久设置。
- 每打开一个新的 PowerShell 窗口，如果需要激活虚拟环境，都要先执行一次临时放行命令。

- 输出中包含 `"status": "pass"`。

### 5.5 检查 OpenCV 视频读取

```powershell
python .\scripts\verify_opencv_video.py
```

通过标准：

- 输出 `Reported FPS: 24.00`。
- 输出 `Resolution: 640x360`。
- 输出 `Decoded frames: 48`。
- 最后一行包含 `PASS: OpenCV created and read the local test video.`。

实际输出示例：

```text
OpenCV version: 5.0.0
Video: D:\program\weizhixianjue\simulation\videos\stage1_test.mp4
Reported FPS: 24.00
Resolution: 640x360
Decoded frames: 48
First frame shape: (360, 640, 3)
PASS: OpenCV created and read the local test video.
```

| 输出 | 含义 |
|---|---|
| `OpenCV version: 5.0.0` | 当前使用的 OpenCV 版本为 5.0.0 |
| `Video: ...\stage1_test.mp4` | 正在读取的测试视频路径 |
| `Reported FPS: 24.00` | 视频文件记录的帧率为 24 帧/秒 |
| `Resolution: 640x360` | 画面宽度 640 像素，高度 360 像素 |
| `Decoded frames: 48` | 成功解码并读取了 48 帧，没有中途失败 |
| `First frame shape: (360, 640, 3)` | 第一帧为高度 360、宽度 640、3 个颜色通道 |
| `PASS` | OpenCV 视频创建和读取验收通过 |

`Decoded frames` 与 FPS 的关系：

```text
48 帧 ÷ 24 帧/秒 = 2 秒
```

这与测试视频的 2 秒长度一致，说明视频没有被提前截断。

`First frame shape` 中的 `3` 表示每个像素有 3 个颜色通道。OpenCV 默认使用 **BGR** 顺序，而不是常见的 RGB 顺序：

```text
B = Blue / 蓝
G = Green / 绿
R = Red / 红
```

该验收通过说明后续可以正常执行：

```text
读取上传视频 → 抽帧 → 送入 YOLO 检测 → 目标跟踪
```

本项只验证视频读取基础能力，不代表 YOLO 检测准确率。

## 6. 启动后端

后端需要单独占用一个 PowerShell 窗口。该窗口用于持续运行服务和显示访问日志，**不能在后端运行期间继续输入其他普通命令**。

### 6.1 启动命令

在第一个 PowerShell 窗口中执行：

```powershell
Set-Location "D:\program\weizhixianjue"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\.venv\Scripts\Activate.ps1
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

### 6.2 启动成功的日志

看到类似以下内容表示后端启动成功：

```text
INFO: Will watch for changes in these directories: ['D:\\program\\weizhixianjue']
INFO: Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO: Started reloader process [18280] using WatchFiles
INFO: Started server process [14624]
INFO: Waiting for application startup.
INFO: Application startup complete.
```

| 日志 | 含义 |
|---|---|
| `Will watch for changes...` | 监听项目文件变化，修改代码后会自动重启服务 |
| `Uvicorn running on ...` | 服务已经在 `127.0.0.1:8000` 端口运行 |
| `Started reloader process` | 自动重载进程已启动 |
| `Started server process` | Web 服务进程已启动 |
| `Waiting for application startup` | 正在执行应用启动流程 |
| `Application startup complete` | 应用启动完成，可以接收请求 |

### 6.3 “卡在这里”是正常状态

出现 `Application startup complete` 后，窗口没有继续输出并停在等待状态，是正常现象。

这不是卡死，而是后端正在等待浏览器或其他程序发送 HTTP 请求。不要按 `Ctrl + C`，也不要关闭这个窗口。

## 9. 常见问题

### 9.1 `npm` 提示禁止运行 `npm.ps1`

不要修改系统级执行策略，直接使用：

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd run build
```

### 9.2 PowerShell 禁止运行 `Activate.ps1`

这是 Windows 的默认安全策略，不是项目环境损坏。

在当前 PowerShell 窗口临时放行，然后重新激活：

```powershell
Set-Location "D:\program\weizhixianjue"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\.venv\Scripts\Activate.ps1
```

该操作仅对当前窗口有效，不会修改系统级或当前用户的永久执行策略。

如果仍然无法激活，可以不激活环境，直接使用虚拟环境中的 Python：

```powershell
Set-Location "D:\program\weizhixianjue"
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

### 9.3 端口被占用

查看 8000 端口：

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen
```

查看进程：

```powershell
Get-Process -Id <OwningProcess 对应的 PID>
```

如果确认是旧的 Uvicorn 进程，可以停止：

```powershell
Stop-Process -Id <PID> -Force
```

### 9.4 `nvcc` 找不到

当前机器没有安装完整 CUDA Toolkit，这是正常情况。

本项目的 PyTorch CUDA 运行库由官方 wheel 提供，不需要 `nvcc`。只有后续需要自行编译 CUDA 扩展时，才需要安装 CUDA Toolkit。

### 9.5 YOLO 权重或测试证据不在 Git 中

`vision\weights\*.pt` 和 `simulation\evidence\*` 被 `.gitignore` 排除，这是为了避免把大文件和可重新生成的结果提交到 Git。

本地文件仍然存在：

```text

D:\program\weizhixianjue\simulation\evidence\yolo_stage1\stage1_bus.jpg
```

### 9.6 后端测试为什么启动真实 Uvicorn

当前 `Starlette 1.7.0` 的进程内 `TestClient` 在本机 `Python 3.10 + httpx2 2.14.0` 组合下会阻塞，因此项目测试改为启动真实 Uvicorn 子进程。这种方式更接近实际运行环境。
